# ChessProgress — дашборд шахматного прогресса KvLGn

Личная страница прогресса: партии с Lichess, задачи, дебюты, активность и автоматические выводы.
Открывается двойным кликом по `KvLGnChessProgress.html` (без сервера). Данные обновляет `update.bat`.

> **Для Claude в новой сессии:** прочитай этот файл целиком, прежде чем что-то менять.
> Раздел «Принятые решения» объясняет, что сделано намеренно и не требует исправлений.

## 2. Сайт и облако (GitHub)

- Папка `progress/` — git-репозиторий **github.com/KvLGn/KvLGnChessProgress** (публичный).
- Сайт: **https://kvlgn.github.io/KvLGnChessProgress/** (GitHub Pages, ветка `main`, корень). Открывается с айфона.
- **GitHub Actions** (`.github/workflows/update.yml`) каждый час в :07 UTC запускает `scripts/update.mjs` и коммитит
  `data/` и `scripts/cache/`, если что-то изменилось. Ручной запуск: вкладка Actions → «Run workflow».
- Токен Lichess в облаке — секрет репозитория `LICHESS_TOKEN` (добавлен через API; через веб-форму GitHub не сохранял — ошибка).
  В облаке нет папки `claude/`, поэтому `game-log.md` / `puzzle-rating.md` обновляются только на ПК.
- **ПК и облако пишут в одни файлы** — поэтому `update.bat` сначала делает `git pull`, потом `git push`.
  Облако перед отправкой тоже подтягивает свежие коммиты (`git pull --rebase -X theirs`, до 3 попыток; при споре в данных побеждает облако) — иначе запуск падал, если в эти минуты что-то отправили с ПК (30.09 15:53 UTC).
- **Расписание GitHub ненадёжно:** за 30.09 вместо ежечасных было 2 запуска по cron. Если данные давно не обновлялись — `update.bat` или Actions → «Run workflow».
- **Правило для Claude:** после правок страницы, скрипта или `data/plan.js` — `git add`, `git commit`, `git push`
  (из папки `progress/`), иначе на сайте останется старая версия. Сайт обновляется ~1 мин после push.
- В архив `archive/` и `node_modules/` в git не попадают (`.gitignore`). Коммиты — от `KvLGn@users.noreply.github.com`.
- GitHub отключает расписание, если в репозитории 60 дней нет активности (коммиты бота считаются, только если данные менялись).

## 2а. Как текут данные

```
Lichess API ──(update.bat → scripts/update.mjs)──► data/games.js, data/puzzles.js
                                               └─► claude/game-log.md, claude/puzzle-rating.md
data/plan.js (вручную) ─────┐
data/*.js ──────────────────┴──► KvLGnChessProgress.html (читает window.GAMES / PUZZLES / PLAN;
                                  текущий этап, PROFILE и OPENINGS {current/next/planned} считает сама)
```

Что забирает `update.mjs`:
- **Партии**: `/api/games/user/KvLGn` с `accuracy`, `division`, `opening`. В `GAMES` попадают только
  партии **с компьютерным анализом** (есть точность по фазам). Партии без анализа скрипт перечисляет
  в консоли и в `game-log.md` — анализ нужно запросить на Lichess вручную (API этого не умеет).
- **Рейтинговые партии** → `RATING_GAMES` (для ELO; анализ не нужен).
- **Задачи**: `/api/puzzle/activity` (все попытки), `/api/puzzle/dashboard/90` (перфоманс по темам,
  русские названия тем), `/api/user` (текущий рейтинг задач).
- **Дебют каждой задачи**: `/api/puzzle/{id}` → партия-источник → самая глубокая позиция из базы
  lichess-org/chess-openings (с учётом перестановок ходов через chess.js). Кэшируется, запрашиваются
  только новые задачи. Первый запуск ~1 мин, дальше секунды.
- **История рейтинга задач**: Lichess её не хранит — скрипт пишет снимок «рейтинг на сегодня» при каждом
  запуске (одна точка на день). Ранние точки 28.09 и 29.09 взяты из ручной таблицы.

**Игровой день** везде (скрипт и страница): по Москве, партии до 05:00 относятся к предыдущему дню.

### Форматы данных

`data/games.js`
```js
window.GAMES_UPDATED = '30.09.2026 10:57';
window.GAMES = [ {id, date:'29.09', day:'2026-09-29', opening, eco, color:'white'|'black',
                  result:'win'|'lose'|'draw', moves, acc, debut, mid, end /* null = эндшпиля не было */,
                  inacc, mistakes, blunders, acpl, engine:'Stockfish 3', section, ir?,
                  opp:'ai'|'human', lvl /*1–8|null*/, rated, speed /*bullet|blitz|rapid|classical|correspondence…*/ }, ... ];   // старые → новые
window.RATING_GAMES = [ {id, date, day, perf:'rapid', before, diff, after}, ... ];
// у партии с анализом ещё: bl (зевки по типам), ev (перевес по полуходам), mv (ходы SAN), start, dur, how, div, plies,
//   ms [[p, [всего, [[ход, партий]…], 'm' | 'l'], {'дебют/мастер': [[ход, раз]…]}]…] — «Мастера» (ключ с дебютом: italian/Carlsen — один мастер бывает в студиях разных дебютов): позиция перед моим ходом p + 1, база мастеров Lichess
//     ('m'; если у мастеров меньше 20 партий — игроки Lichess 2000+, 'l') и ходы мастеров из студий plan.js (только его цветом), первые 15 своих ходов,
//   ts — конец партии (мс UTC, для «!» свежей партии), mt {полуход: N} — мат в N после полухода (> 0 — у меня, < 0 — у соперника), jd [[полуход, 'I'|'M'|'B', лучшая линия]] — оценки ходов движком (обе стороны)
```
`data/puzzles.js`
```js
window.PUZZLES = { rating, total,
  history:    [{day, date, rating}],                 // снимки рейтинга по дням
  themeNames: {fork:'Вилка', ...},                    // русские названия тем
  themeStats: {fork:{nb, first, perf}, ...},          // перфоманс Lichess по темам (с 1-й попытки, 90 дней)
  global:     {nb, first, perf},
  attempts:   [{day, date, id, win, r /*рейтинг задачи*/, themes, op /*дебют*/,
                mode:'mix'|'open'|'theme', tr /*название тренировки*/}] };
```
`data/plan.js` — см. раздел 5 «Частые задачи» и `AI-PROMPT.md`. В каждой партии есть поле `first` — первый ход белых (по нему определяется дебют из плана за чёрных).

## 5. Частые задачи

**Обновить данные** — ничего не делать (облако раз в час) или двойной клик по `update.bat` (сразу + заметки claude/*.md), затем F5.

**Опубликовать правки страницы** — из `progress/`: `git add -A && git commit -m "…" && git push`.

**Студии мастеров** — в `data/plan.js` у студии поле `ids` (id всех частей, первая = `id`); студия должна быть открыта хотя бы по ссылке (Unlisted), иначе скрипт её не скачает. Сейчас так записаны: Итальянская — Карлсен (2 части, 51 партия белыми) и Со (3, 121); Сицилианская — Карлсен (7 частей, 331 партия чёрными); Славянская — Крамник (2 части, 53 чёрными). Мастер берётся только цветом дебюта (поле Black у чёрных дебютов), имена — «Фамилия, …» в любом варианте. Остальные студии (Лондонская, Французская, Испанская, Найдорф) закрыты и частей в плане нет.

**Этапы и дебюты** — только в `data/plan.js` (инструкция в начале файла, промпт — `AI-PROMPT.md`). Этап переключается сам по правилу `rule`
(2 пятёрки подряд против бота этапа каждым цветом; в каждой 4+ побед, медиана точности ≥ 70%, проигрыш — точность ≥ 55% и зевков ≤ 2).
Выполненные этапы **записывает update.mjs** в `data/progress.js` (раз и навсегда): сайт берёт их оттуда и считает только текущий, поэтому правка правила или плана не откатывает пройденное. Прошедшие этапы в plan.js не удалять и не переставлять — сайт покажет предупреждение.
**Защита plan.js**: сайт проверяет файл (`STAGES.validatePlan`: этапы, engine, colors, id дебютов и ссылки на них, длина названий, студии). Ошибка — красная плашка с причиной, и сайт работает на последней рабочей копии плана из браузера (localStorage `planGood`); предупреждение — жёлтая плашка. update.mjs при ошибке в плане этапы не обновляет и пишет причину в консоль. Статус дебюта (изучаю / далее / в планах) считается от этапа;
изученные остаются в «изучаю» вторым планом. Для чёрных дебют из плана определяется по первому ходу бота (`vs`).
Копия плана для людей — `claude/training-plan.md` (кратко) и `claude/repertoire.md` (PGN-файлы).

**Добавить правило в «Итоги»** — функция `buildVerdicts`:
`add(тип, вес, коротко, ссылка|null, подробно, группа, подгруппа, действие)`; тип `'bad' | 'good' | 'tip'`; чем больше вес, тем выше пункт; группа — из `VD_GROUPS`; действие — функция по клику (панель «Итоги» закроется сама), например `anOpen(g, ply, 'bl')`, `mrOpenSection(g, 'turn' | 'opp')`, `gsChart('metrics', false)`, `pinSeries(k)`.
Короткий текст должен помещаться в строку (~45 символов), подробности уходят во всплывающую подсказку.

**Меню (бывший поиск)** (`gsIndex` — пункты, `mnPlace` — их место в меню) содержит: разделы, ответы, виды графика, фильтры, **режим партии** (Stockfish N, компьютер/люди, контроль — только встречающиеся), **активность** (прошлая неделя/месяц…, поражения/победы по дням), **дни** («Сб 26.09» — открывает неделю и выделяет день), **тренировки задач**, **сравнения** (в «Разделах» — «Сравнение партий» ⏷ с вариантами последние 3 / 5 / 7 vs предыдущие: пункт с `children`, раскрывается `gsOpenKey`; в группе «Сравнения» — победы vs поражения, белыми vs чёрными, последний игровой день vs предыдущий, эта неделя vs прошлая — сразу экран сравнения через `gsCompareGames` / `gsCompareDays`), **студии** мастеров из plan.js, **«Справка»**, Lichess, партии, дебюты, темы, итоги; группа **«Анализ»** (скрывается с графиком; видна и без запроса — пустой поиск показывает «Разделы», «Анализ» и «Ответы»): «Новая партия с ошибками» (только когда горит «!»), «Разбор последней партии», «Зевки / Маты на доске», «Сравнить с мастерами», «Сравнить с Карлсеном (Итальянская)» — по студиям плана; в «Фильтрах»: «Партии за сегодня / за 7 дней», «Мой дебют: …», «Упущенные маты: N»; в «Ответах» (с таблицей): «Перелом последней партии» — отчёт с панелью «i» и переломом на графике.

## 6. Принятые решения (не «исправлять»)

**Смысл и данные**
- Страница делается **на будущее**: «Последние 30 партий», «10 партий за 2 недели», колонка «ИР», ELO «?»,
  окно «за 20 игр» — заготовки, которые заполнятся сами.
- Ссылка Lichess ведёт на **главную** страницу, а не на профиль.
- Названия дебютов — **полностью, как в Lichess**.
- **Перфоманс** режимов задач (микс/дебют) считается по истории попыток, где Lichess засчитывает и решения
  со второй попытки, поэтому он выше рейтинга. Сравнивать можно только режимы между собой. Поэтому в карточке
  задач вместо перфоманса — «Неделя N» и ✓/✗; перфоманс остался только в раскрытой панели.
  Темы задач — перфоманс самого Lichess (честный, с первой попытки).
- Режим задач определяется автоматически: **6+ подряд** из одного дебюта → тренировка по дебюту;
  6+ подряд с общей тактической темой → тренировка по теме; иначе микс. Порог 4 давал ложные срабатывания.
- «▲+N сегодня» у рейтинга задач — **только в дни, когда решались задачи**.
- «Неделя» в задачах — текущая календарная неделя, а если в ней пусто — последняя неделя с задачами (с датами).
- Средние/прирост: окно 10 → «5 против 5», окно 20 → «10 против 10», окно 5 → без прироста.
  Если партий меньше окна — сравнение по доступным, подпись «4 из 10 🔒».
- Серия: дни подряд с партиями; если сегодня ещё не играл, серия не прерывается до конца дня.
- Периоды активности календарные (неделя пн–вс, месяц); «3 месяца» — целыми неделями.

**Внешний вид**
- Эндшпиль на графике **скрыт по умолчанию** (включается кликом по легенде).
- Линии средних **не рисуются**, пока показатель не наведён или не выделен.
- Клик по строке слева — **выделить** линию (повторный клик — снять); клик по легенде снизу — **скрыть/показать**.
- **Без 3D и свечения** у кнопок «Рекорды»/«Активность» и бейджей W/L (пользователь просил убрать).
- Линии графика — исходные цвета с лёгкой прозрачностью; фон побед/поражений заметный (0.14), перегородки между
  партиями тёмные; толстые серые линии — границы дней.
- Шапка: профиль прежнего размера, кнопки-ссылки слева, глаз шапки и меню ☰ справа, полоса не выходит за правую рамку.
- Цвета блоков: задачи — фиолетовый, дебюты — синий, итоги — индиго #6366f1 (насыщенность как у задач и дебютов), между фиолетовым и синим (был салатовый — «ядовитый», заменён 01.10.2026, серый не понравился; смысловые красный / зелёный / жёлтый внутри списков остались), активность — жёлтый, рекорды — фиолетовый, сравнение — изумрудный (#34d399).
