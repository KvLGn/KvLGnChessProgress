# ChessProgress — дашборд шахматного прогресса KvLGn

Личная страница прогресса: партии с Lichess, задачи, дебюты, активность, автоматические выводы и «Справка» — готовые запросы
к нейросетям и письма людям. Открывается двойным кликом по `KvLGnChessProgress.html` (без сервера) или на сайте
**https://kvlgn.github.io/KvLGnChessProgress/**. Данные обновляются сами (облако, примерно раз в час) или `update.bat`.

> **Новому помощнику (человеку или нейросети):** прочитай раздел 0 и раздел 6 «Принятые решения» — там то, что сделано
> намеренно и не требует исправлений. Остальное — справочник: ищи нужный раздел по оглавлению.

## 0а. Если что-то сломалось

Сайт устроен так, что ошибка в одном файле не роняет страницу: партии, график и задачи работают, а сверху — плашка с причиной.
**На самом сайте:** ☰ → «Сервис» → «Если сайт сломался»: «Инструкция» (сама проверяет план, свежесть данных и последние запуски
на GitHub, ниже — шаги) и «Помощь ИИ» (копирует запрос для сильной нейросети: состояние, plan.js, правила — что можно и чего нельзя).
Код — `fixStatus`, `fixGuideHtml`, `fixAiText` (раздел «Если сайт сломался» перед меню). Эта таблица — для случая, когда сайт не открывается совсем.

| Что видно | Что случилось | Что делать |
|---|---|---|
| Красная плашка «data/plan.js с ошибкой — сайт работает на последней рабочей версии» | в plan.js ошибка (часто — после правки нейросетью); сайт взял запасную копию `data/plan-good.js` | вернуть прошлую версию (ниже) или дать нейросети текст плашки и попросить исправить |
| Жёлтая плашка «предупреждения» | план работает, но что-то стоит поправить (длинное название, `const PLAN` вместо `window.PLAN` и т. п.) | не срочно; поправить при следующей правке плана |
| Письмо от GitHub «Run failed: Проверка plan.js» | отправлен сломанный plan.js | то же, что при красной плашке; причина — в письме → «Проверить план» |
| Письмо «Run failed: Обновление данных с Lichess» | один запуск обновления не прошёл (сбой Lichess, спор с правкой с ПК) | обычно ничего — следующий запуск пройдёт сам. Если письма идут много часов подряд — открыть лог, причина в шаге «Забрать данные с Lichess» (раздел 5 «Данные давно не обновлялись») |
| «Обновлено» в подвале давно не менялось | GitHub пропускает запуски по расписанию | `update.bat` с ПК или GitHub → Actions → «Обновление данных с Lichess» → «Run workflow» |
| Сайт выглядит сломанным после правки самого сайта | ошибка в `KvLGnChessProgress.html` | вернуть прошлую версию этого файла (ниже) |

**Вернуть прошлую версию файла без программиста** (на github.com, с телефона тоже):
1. github.com/KvLGn/KvLGnChessProgress → открыть файл (например, `data/plan.js`) → кнопка **History** (часы справа сверху).
2. Найти последнюю версию до поломки (по дате) → у неё кнопка `<>` (файл в этой версии) → **Raw** → скопировать весь текст.
3. Вернуться к текущему файлу → карандаш **Edit** → выделить всё, вставить скопированное → **Commit changes**. Сайт обновится через ~1 мин.

Что защищено автоматически (проверено 01.10.2026: 16 типичных поломок plan.js, 1896 подмен полей неверными типами — проверка не падает,
а каждую принятую страница открывает без ошибок; пропажа и порча файлов данных; пустой и урезанный ответ Lichess):
- **plan.js сломан** — сайт берёт последнюю рабочую копию: `data/plan-good.js` (её сохраняет каждое обновление, когда план исправен;
  есть на любом устройстве) или копию в браузере, если она свежее. Обновление данных тоже берёт её, «Мастера» не пропадают;
  этапы при этом не записываются (запишутся, когда план исправят, с настоящей датой).
- **План прошёл проверку, но страница всё равно не отрисовалась** — она один раз перезагружается на запасной копии
  (флаг `planForce` в sessionStorage) и показывает красную плашку; если не помогло — ошибка не в плане, повторных перезагрузок нет.
- **Каждая правка plan.js** проверяется на GitHub (`.github/workflows/check-plan.yml`): сломан — красный крестик и письмо.
  Проверить на ПК: `node scripts/plan-check.mjs`.
- **Lichess вернул заметно меньше партий или задач** (больше 10% или ноль — сбой) — скрипт ничего не записывает и завершается
  с ошибкой; следующий запуск пробует снова. Небольшое уменьшение — только предупреждение в логе (иначе обновление падало бы
  каждый раз). Все проверки идут до любой записи; `update.bat` при ошибке скрипта ничего не отправляет на GitHub.
- **`data/progress.js` не читается** — скрипт его не перезаписывает (иначе пропали бы записанные этапы).
- **Правка с ПК и обновление облака одновременно** — облако подтягивает правку и отправляет снова (до 3 попыток).
- **60 дней без активности** (GitHub выключает расписание) — не наступят: каждый запуск обновления делает коммит.

## 2. Сайт и облако (GitHub)

- Папка `progress/` — git-репозиторий **github.com/KvLGn/KvLGnChessProgress** (публичный). Сайт — GitHub Pages, ветка `main`, корень.
- **GitHub Actions** (`.github/workflows/update.yml`) 4 раза в час (:07, :22, :37, :52 UTC) запускает `scripts/update.mjs` и коммитит
  `data/` и `scripts/cache/` (время обновления меняется всегда — коммит есть каждый запуск). Ручной запуск: вкладка Actions → «Run workflow».
- **Проверка плана** (`.github/workflows/check-plan.yml`) — при каждом push с изменением `data/plan.js` или `lib/stages.js`.
- Токен Lichess в облаке — секрет репозитория `LICHESS_TOKEN`. В облаке нет папки `claude/`, поэтому `game-log.md` /
  `puzzle-rating.md` обновляются только на ПК.
- **ПК и облако пишут в одни файлы:** `update.bat` сначала `git pull`, потом `git push`; облако перед отправкой делает
  `git pull --rebase -X theirs` (до 3 попыток; при споре в данных побеждает облако). Из Claude: `git pull --rebase -X theirs` перед `git push`.
- **Расписание GitHub ненадёжно**: при «каждый час» за сутки 30.09–01.10 дошло 4 запуска из 24, поэтому просим 4 раза в час.
  Давно не обновлялось — `update.bat` или «Run workflow». GitHub отключает расписание после 60 дней без активности — у нас не
  наступит, пока запуски идут (каждый делает коммит).
- **Версии**: Node 22 (в обоих workflow; поддержка до 04.2027 — потом поднять до следующей LTS), `actions/checkout@v5`,
  `actions/setup-node@v5`, chess.js закреплён в `scripts/package-lock.json`. GitHub заранее пишет в лог запуска, если версия устаревает.
- Сайт обновляется ~1 мин после push. `archive/` и `node_modules/` в git не попадают. Коммиты — от `KvLGn@users.noreply.github.com`.
- **Репозиторий публичный** — всё в `data/*.js` видно всем; «скрытый режим» на странице прячет только экран (решение 30.09.2026).

## 2а. Как текут данные

```
Lichess API ──(update.mjs: облако раз в час или update.bat)──► data/games.js, data/puzzles.js, data/progress.js
                                                            └─► claude/game-log.md, claude/puzzle-rating.md (только ПК)
data/plan.js (вручную) ─────┐
data/*.js ──────────────────┴──► KvLGnChessProgress.html (читает window.GAMES / PUZZLES / PLAN / PROGRESS;
                                  текущий этап, PROFILE и OPENINGS {current/next/planned} считает сама)
```

Что забирает `update.mjs`:
- **Партии** (`/api/games/user/KvLGn` с accuracy, division, opening). В `GAMES` — только партии **с компьютерным анализом**;
  остальные скрипт перечисляет в консоли и в `game-log.md` — анализ нужно запросить на Lichess вручную (API не умеет).
- **Рейтинговые партии** → `RATING_GAMES` (для ELO). **Задачи**: попытки, перфоманс по темам за 90 дней (с русскими названиями),
  рейтинг; дебют каждой задачи (по партии-источнику и базе lichess-org/chess-openings, кэш). **История рейтинга задач** —
  снимок раз в день (Lichess её не хранит; точки 28–29.09 — из ручной таблицы).
- **Зевки по типам** (`blunders.mjs`), **мастера** (`masters.mjs`), **выполненные этапы** (`lib/stages.js` → `progress.js`, раз и навсегда).

**Игровой день** (скрипт и страница): по Москве, партии до 05:00 — предыдущий день.

### Форматы данных
`data/games.js`
```js
window.GAMES_UPDATED = '30.09.2026 10:57';
window.GAMES = [ {id, date:'29.09', day:'2026-09-29', opening, eco, color:'white'|'black', first /* первый ход белых */,
                  result:'win'|'lose'|'draw', moves, acc, debut, mid, end /* null = эндшпиля не было */,
                  inacc, mistakes, blunders, acpl, engine:'Stockfish 3', section, ir?,
                  opp:'ai'|'human', lvl /*1–8|null*/, rated, speed /*…|correspondence*/ }, ... ];   // старые → новые
window.RATING_GAMES = [ {id, date, day, perf:'rapid', before, diff, after}, ... ];
// у партии с анализом ещё: bl (зевки: m ход, s сыграно, t тип, p фаза, b лучше, d цена), ev (перевес по полуходам),
//   mv (ходы SAN), start, dur (секунды), how, div (полуходы начала фаз), plies, ts (конец, мс UTC — для «!» свежей партии),
//   mt {полуход: N} — мат в N (> 0 у меня, < 0 у соперника), jd [[полуход, 'I'|'M'|'B', лучшая линия]] — оценки движка обеих сторон,
//   ms [[p, [всего, [[ход, партий]…], 'm'|'l'|'a'], {'дебют/мастер': [[ход, раз]…]}]…] — «Мастера»: позиция перед моим ходом p+1,
//   база Lichess (m — мастера, l — игроки 2000+, a — любители 1800+, следующая ступень — если на предыдущей < 20 партий)
//   и ходы мастеров из студий plan.js (только цветом дебюта), первые 20 своих ходов
```
`data/puzzles.js`
```js
window.PUZZLES_UPDATED = '…';
window.PUZZLES = { rating, total, history: [{day, date, rating}], themeNames: {fork:'Вилка', …},
  themeStats: {fork:{nb, first, perf}, …} /* перфоманс Lichess по темам, с 1-й попытки, 90 дней */, global: {nb, first, perf},
  attempts: [{day, date, id, win, r /*рейтинг задачи*/, themes, op /*дебют*/, mode:'mix'|'open'|'theme', tr}] };
```
`data/plan.js` — инструкция в начале самого файла; правила — раздел 5.

### 3а. Итоги

  перед добавлением правила поищи там — многие уже есть, например «3 поражения подряд → сделай паузу»), `add(тип 'bad'|'good'|'tip', вес, коротко, ссылка, подробно, группа, подгруппа, действие)`.

  **«К цели этапа»** — оси = условия `rule` на партиях этапа, центр — первые W партий этапа, зелёный контур — требование правила.

- **Кнопка «i» у «Зевки»** — режим типов зевков: столбики по типам, легенда-таблетки (клик — скрыть тип, `blHidden`) (`blMode`).

- **Сравнить** (при выбранной колонке / дне): экран из двух карточек и строк с разницей; «Зевки ▾» раскрывает типы (`cmpMode`, `aCmpMode`).

### 3д. Скрытый режим
- Шапка, график и партии скрываются по отдельности своими глазами. Клик по аватарке — общий глаз: **скрытый режим** (`hush.mode`,
  скрыто всё; вернуть — только аватаркой; глаза частей невидимы, но держат место — кнопки рядом не съезжают). Зелёный глаз под

- Скрытие не сбрасывает выбор: состояние запоминается и возвращается (`snapHush` / `restoreHush`). Сохраняется между перезагрузками.
- Скрытый график: колонки и столбики пустые и не нажимаются, без подсказок (`#chart .hit`, проверка `hush.chart` в `showTooltip` и клике);

  Кнопка «i» у зевков приглушена и не нажимается, легенда типов скрыта (режим зевков не сбрасывается); подсказка, открывшаяся
  за 0,25 с анимации глаза, закрывается (`hideTooltip` в `applyHush`).
- Скрытая таблица (своим глазом или в скрытом режиме): фильтры видны, но приглушены и не нажимаются, число партий в счётчике — «—»
  (CSS `body.hush-table #filters`, как у «Фильтра графика»).

### 3е. Дебюты
- Статус считается от этапа плана: этап начался → «Изучаю» (вместе с дебютами пройденных этапов), этап позже → «Далее», без этапа → «В планах».

  попытка дебюта (если белый дебют один), за чёрных — по первому ходу бота (`vs`). `board` — где дебют получился на доске (название Lichess),
  `away` — куда ушли остальные. Карточка: «11 партий · 55% побед · на доске 4».
- Несколько изучаемых дебютов (этап 2+): заголовок карточки — карусель (`startOpCurCarousel`), в панели стрелки ‹ ›.

### 3ж. Справка (запросы для ИИ и письма людям)
Кнопка «📋 Справка» (`#helpBtn`, неактивна, если скрыта любая часть страницы) открывает окно 640 × min(86vh, 760px).

**Шапка окна:** ⓘ (подсказка) · **«Для кого ▾»** (`aiMode`: ИИ / человек) · **«Суть вопроса ▾»** (`aiKind`: «Совет» зелёный /
«Техническая» жёлтая — правка plan.js) · **«Сильная | Простая»** (`aiModel`, только для ИИ; в технической — всегда «Сильная») · RU | EN (`aiLang`).
Всё запоминается в localStorage (`aiMode`, `aiKind`, `aiModel`, `aiLang`). **Клик по пункту — запрос скопирован** (`copyText`, `helpToast`).

**Пункты** — `AI_ASKS`: группы «Разбор игры» · «Тренировки» · «Дебюты» · «Прогресс» · «План» (техническая). У пункта: `t`/`tEn` — заголовок,
`ru`/`en` — просьба к ИИ, `h`/`hEn` — тот же вопрос человеку, `d` — ключ данных. Особые пункты:
- **Дебюты** строятся из плана (`dyn`, `aiItems`): на каждый изучаемый дебют «Что учить в дебюте «X»» с подпунктами (`sub`: «Линии по моим
  партиям» — `opLines`, «Когда бот уходит / Когда «X» не получается» — `opAway`) и «Типичные планы после дебюта» (`plans`); пакет — про дебют
  пункта (`AI_CUR_OP`). Для дебютов за чёрных — свои формулировки (дебют выбираю я, а не бот).
- **«План на сегодня / на неделю»** — кнопки времени 30 мин / 1 / 2 / 3 часа (`times`, `AI_MIN`): от времени зависят вопрос, условия и шаблон.
- Поля в квадратных скобках (`[впиши перед отправкой]`) — заполнить перед отправкой; ИИ при незаполненных полях спрашивает.

**Как собирается запрос** (`helpText`):
- **ИИ, сильная** (`aiText`): «Задача:» → правила (`AI_PROMPT.base`, для плана ещё `AI_PROMPT.plan`) → `<сводка>` (`aiSummary`: этап и
  пятёрки, партии и фазы, дебюты, задачи, активность, выводы «Итогов») → `<данные_под_вопрос>` (`AI_DATA[d]`) → для плана весь `plan.js`
  (`planSource`) → «Условия ответа» (`AI_COND`) с самопроверкой → «Вопрос:».
- **ИИ, простая** (`aiTextSimple`, для Алисы / GigaChat): «Задача» → 5 коротких правил → `<данные>` (`AI_SIMPLE[d]`, 1–2 тыс. знаков, выводы
  посчитаны заранее) → условия → шаблон ответа (`AI_SIMPLE_TPL[AI_SIMPLE_KIND[d]]`) → «Проверка условий: … — да / нет» → вопрос.
- **Человек, совет** (`humanText`, `PLAIN = true`): письмо «Привет! Учусь играть…», вопрос `h`, «коротко обо мне» (`aiAbout`), 3 партии по
  теме со ссылками (`AI_REFS`), статистика по вопросу (без номеров партий и внутренних терминов; ходы — ссылками на Lichess).
- **Человек, техническая:** задание программисту — приветствие, просьба, контекст, данные, «Как устроено» (правило, статусы дебютов,
  термины, засчитывание задним числом, JS), «нет доступа — пришли текст plan.js», шаги на GitHub, правила формата, весь `plan.js`.

**Данные под вопрос** (`AI_DATA` / `AI_SIMPLE`) — у каждого пункта свои, всегда за окно (последние 5 / 10 / 20 партий, сегодня, 7 / 14 дней),
ничего «за всё время». Общие помощники: партия одной строкой (`aiGame`, в простом — `aiSGame`), зевок (`aiBl`), перелом (`aiTurn`), ошибки бота
(`aiOpp`), маты (`aiMates`), отход от мастеров (`aiMs`, ходы до отхода — `aiLineTo`), цель этапа (`aiGoalCond` — какие условия мешают,
`aiGoalWin` — окно пятёрок, `toGoalText` — точный итог «ещё минимум K партий, из них ≥ W побед», `winsToGoal`), темп (`aiGoalPace`), свежесть
(`aiFresh`), длительность партии (`aiDurLine`), изучаемый дебют (`aiCurOps`), неделя к неделе (`aiWeekSplit`).

**Правила, выведенные проверками** (на DeepSeek, Алисе, Sonnet, Haiku; не ломать без новой проверки):
- Числа **подписаны**, сравнения **посчитаны заранее** (самая слабая фаза, частоты, «тоже 3» при равенстве, «X из Y (P%)» — `aiOf`),
  списки упорядочены по главному числу с подписью порядка (`aiSortBy`), один пункт — одна строка: иначе модели путают «число не к тому».
- Окна у чисел названы явно («последние 10 партий», «#2–#11»); сравнивать только числа из одного окна (неделя к неделе — поровну партий).
- Условия ответа — **у места ответа**, а не в начале (слабые модели забывают первую строку); строка самопроверки в конце.
- Жёсткого формата, словаря и обращения нет — с ними ответы хуже (A/B на DeepSeek и Алисе). PGN / FEN выключены (`AI_FEN = false`).
- Где вопрос про шахматные идеи (планы после дебюта, почему ход мастеров лучше) — в условиях **разрешены общие знания** с пометкой
  «обычно», иначе правило «не придумывай» давало пустой ответ.
- Технические пакеты: этап только Stockfish 1–8; один чёрный дебют на ход бота среди всех изучаемых; конфликт — не присылать plan.js;
  замену дебюта текущего этапа — согласовать; правка правила может засчитать этап задним числом; поля `[ ]` — спросить; «минимум» ≠ срок.
- EN — всё на английском (кроме сводки и советов сайта — они только на русском, это помечено); названия тем задач — как на Lichess (`PZ_EN`).

**Как проверять «Справку»** (после правок): синтаксис (раздел 5) + в Chrome headless собрать все пакеты: перебрать режимы ×
языки × пункты (`AI_ASKS`, `aiItems`, у пунктов с `sub` — подпункты, с `times` — каждое время), вызвать `helpText(...)` и убедиться, что
пакетов прежнее число (сейчас 174) и ни в одном нет `undefined`, `NaN`, `[object`. Смысл проверять прогоном на модели: ответ сверить с
данными пакета, plan.js из ответа — через `STAGES.validatePlan` и `STAGES.evalStages` (текущий этап не должен меняться без намерения).

## 5. Частые задачи

**Обновить данные** — ничего не делать (облако) или `update.bat` (сразу + заметки `claude/*.md`), затем F5.

**Данные давно не обновлялись** — время обновления видно в футере (`GAMES_UPDATED` в `data/games.js`). Запустить `update.bat`
или GitHub → Actions → «Run workflow». Причины по порядку: расписание GitHub пропускает запуски; запуск упал (лог во вкладке Actions);
истёк секрет `LICHESS_TOKEN`; новая партия **без компьютерного анализа** (в данные не попадает — запросить анализ на Lichess; список
таких партий — в консоли `update.bat` и в `claude/game-log.md`); ошибка в plan.js (данные обновляются, этапы — нет).

**Опубликовать правки** — из `progress/`: `git add -A && git commit -m "…" && git pull --rebase -X theirs && git push`.

**Этапы и дебюты** — только `data/plan.js` (инструкция в начале файла). Проще всего — «Справка» → «Техническая»: готовое задание с
данными и правилами. Ключевое:
- Этап переключается сам по `rule` (2 пятёрки подряд против бота этапа каждым цветом этапа; в каждой 4+ побед, медиана точности ≥ 70%,
  невыигранная партия — точность ≥ 55% и зевков ≤ 2). Этап — только Stockfish 1–8.
- Выполненные этапы **записывает update.mjs** в `data/progress.js` раз и навсегда; прошедшие этапы в plan.js не удалять и не переставлять.
  Правка `rule` / `engine` / `colors` текущего этапа пересчитывается сразу и может засчитать этап задним числом.
- **Защита plan.js:** сайт проверяет файл (`STAGES.validatePlan`): ошибка — красная плашка с причиной и последняя исправная копия из
  браузера (`planGood`); предупреждение — жёлтая. update.mjs при ошибке этапы не обновляет.
- «Изучаю» — дебюты текущего **и всех пройденных** этапов (`OPENINGS.current`). Поэтому за чёрных — один дебют на каждый первый ход бота
  среди всех изучаемых одновременно; иначе партии, где не получился ни один из двух, молча не привяжутся к плану (`planOpening` → `maybe`).
  `validatePlan` предупреждает об этом жёлтой плашкой.
- **Перед правкой `rule` / `engine` / `colors` текущего этапа** прогнать расчёт со старым и новым планом и сравнить текущий этап:
  ```
  node -e "global.window=global; const f=require('fs'); eval(f.readFileSync('lib/stages.js','utf8')); eval(f.readFileSync('data/games.js','utf8')); eval(f.readFileSync('data/progress.js','utf8')); eval(f.readFileSync('data/plan.js','utf8')); console.log('этап', STAGES.evalStages(GAMES, PLAN, PROGRESS).idx + 1)"
  ```
  (запускать из папки `progress/`). Если номер вырос — этап засчитается задним числом, и `update.mjs` при ближайшем запуске запишет это в `progress.js` навсегда.
- Тексты правила в «Справке» и на сайте берутся из `RULE` (`stageRuleText`, `toGoalText`, …) — после смены `rule` менять их не нужно.
- **Лимиты длины названий** (этап 50, дебют 22, мастер 12) — в `lib/stages.js` (`LIMITS`); их же берут проверка плана, «Справка» и письма.
  При смене лимита поправить ещё текст в шапке `data/plan.js` и в `AI-PROMPT.md`.

**Студии мастеров** — в `data/plan.js` у студии `ids` (id всех частей, первая = `id`, число = `parts`) и при нужде `aka` (другие написания
фамилии в PGN, например `['Kortschnoj']`); студия должна быть открыта хотя бы по ссылке (Unlisted). Мастер берётся только цветом дебюта.

## 6. Принятые решения (не «исправлять»)

**Смысл и данные**
- Страница делается **на будущее**: «Последние 30 партий», «10 партий за 2 недели», колонка «ИР», ELO «?», окно «за 20 игр» — заготовки.
- Ссылка Lichess ведёт на **главную**, а не на профиль. Названия дебютов — **полностью, как в Lichess**.
- **Перфоманс** режимов задач (микс/дебют) выше рейтинга (Lichess засчитывает и вторую попытку) — в карточке вместо него «Неделя N» и ✓/✗.
  Темы задач — перфоманс самого Lichess (с первой попытки).
- Режим задач определяется сам: **6+ подряд** из одного дебюта → по дебюту, с общей темой → по теме, иначе микс (порог 4 давал ложные).
- «▲+N сегодня» — только в дни с задачами. «Неделя» в задачах — текущая календарная или последняя с задачами.
- Средние/прирост: окно 10 → «5 против 5», 20 → «10 против 10», 5 → без прироста; мало партий — «4 из 10 🔒».
- Серия: дни подряд с партиями; не прерывается до конца сегодняшнего дня. Периоды активности календарные.
- Все три колонки «Итогов» — автоматические; из plan.js — только этап и правило.
- В «Справке» в письмах людям нет записи ходов — только ссылки на партию и ход (решение пользователя).

**Внешний вид**
- Эндшпиль на графике **скрыт по умолчанию**; линии средних — только при наведении / выделении.
- Клик по строке слева — **выделить** линию; клик по легенде — **скрыть/показать**.
- **Без 3D и свечения** у кнопок и бейджей.
- Цвета блоков: задачи — фиолетовый, дебюты — синий, итоги — индиго #6366f1, активность — жёлтый, рекорды — фиолетовый,
  сравнение — изумрудный #34d399, «Справка» «Техническая» — жёлтая.

## 8. Отложено и планы

  этапы только против Stockfish 1–8 (`stageGame` в `lib/stages.js`). Нужен новый тип этапа «бот с рейтингом X» (не уровень Stockfish) и
  правило, какие партии против него идут в цель. Учесть: такие боты обычно играют с часами — появятся цейтноты.
- Испанская: ids студий — когда понадобится.
- Задачи в режиме «Активность» (столбики задач по дням) — не сделано.
- Колонка «ИР» заполнится сама, когда появятся рейтинговые партии.
